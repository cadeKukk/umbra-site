In the app

Six slabs. One switch.

The cube is the control. Apart and gray means off. Tap it and the pieces close into one white block: every tracker name on the phone now gets a dead answer. The Apps tab fills itself from what the phone resolves, and gets exact when you share Apple's own privacy report to it.

How it works

One route into the dark.

Every app on the phone has to ask a name server before it can talk to anyone. Umbra becomes that name server. Only DNS enters the tunnel; everything else takes its normal path, so the battery barely notices.

10.7.0.1

The tunnel answers to one address

iOS is told that its DNS server lives at a private address, and that the only route into the tunnel is to that address. Web traffic never enters.

0.0.0.0

Trackers get a dead answer

A name on the blocklist, or on your own block list, is answered with the null address. The app believes the tracker does not exist and moves on. Your allow list wins over everything.

DoH

Everything else is resolved over HTTPS

Allowed names are forwarded, encrypted, to a resolver you pick. Quad9 by default. The resolver's own name is answered from fixed addresses so the tunnel never has to ask itself.

7 d

The log stays and then leaves

Every query is written to a local database and deleted after seven days. No account, no sync, no telemetry.

What iOS allows

Four walls, four honest answers.

An iPhone that is not managed by a company keeps apps blind to one another. Umbra does not pretend otherwise. Each wall got a substitute that is real.

Umbra for Mac, in design

The Mac can see more.

macOS lets a system extension see which app opens each connection, so on the Mac, per-app rules will be real rather than estimated. This is a working mock on simulated traffic. Turn the shield off, block a tracker from the Apps view, or let another VPN take over.
